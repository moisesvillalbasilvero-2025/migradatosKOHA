🎯 MEJORAS DE RENDIMIENTO

VELOCIDAD DE PROCESAMIENTO:

REINDEXACIÓN:
  Antes:    Por cada lote (múltiples veces)

  Mejora:   -90% TIEMPO DE REINDEX 🔄

PARALELIZACIÓN:
  Antes:    Secuencial (1 core)
  Ahora:    Paralelo (multi-core)
  Mejora:   ESCALABLE A N CORES 🖥️

🚀 CÓMO USAR - EJEMPLOS RÁPIDOS
═══════════════════════════════════════════════════════════════════════════

1. USO MÁS SIMPLE (Recomendado):
   ─────────────────────────────────
   ./importar_rapido.sh archivo.csv

   → Balance perfecto velocidad/seguridad
   → Configuración automática
   → Validación incluida


2. MÁXIMA VELOCIDAD:
   ─────────────────────────────────
   ./importar_rapido.sh archivo.csv --fast

   → 8 workers paralelos
   → Chunks de 5000 registros
   → Sin validación previa
   → USAR PARA: > 50k registros


3. MODO SEGURO:
   ─────────────────────────────────
   ./importar_rapido.sh archivo.csv --safe

   → Validación completa previa
   → Chunks conservadores (1000)
   → USAR PARA: Datos no confiables


4. MÚLTIPLES ARCHIVOS:
   ─────────────────────────────────
   ./importar_rapido.sh --batch ING.csv MED.csv POL.csv

   → Procesa todos en secuencia
   → Validación de cada uno
   → Resumen al final


5. ANÁLISIS PREVIO:
   ─────────────────────────────────
   ./benchmark_comparacion.sh archivo.csv

   → Estima tiempo de importación
   → Recomienda mejor método
   → Verifica recursos del sistema


═══════════════════════════════════════════════════════════════════════════
🔧 OPTIMIZACIONES TÉCNICAS IMPLEMENTADAS
═══════════════════════════════════════════════════════════════════════════

✓ Procesamiento paralelo con multiprocessing.Pool
✓ Chunks más grandes (2000-5000 vs 500)
✓ Commits optimizados (1000-3000 vs 500)
✓ Caché en memoria para verificaciones BD (TTL: 1h)
✓ Reindexación única al final (vs por lote)
✓ Buffer de escritura de logs (reduce I/O)
✓ Validación on-the-fly (vs pre-validación completa)
✓ Streaming de procesamiento (vs carga completa)
✓ Liberación de memoria caché del SO antes de reindex
✓ Métricas de rendimiento en tiempo real

═══════════════════════════════════════════════════════════════════════════
⚠️ LIMITACIONES Y CONSIDERACIONES
═══════════════════════════════════════════════════════════════════════════

1. RECURSOS DEL SISTEMA:
   • Mínimo recomendado: 4 cores, 8GB RAM
   • Óptimo: 8 cores, 16GB RAM
   • Si menos recursos: usar --workers 2 --chunk-size 1000

2. RECUPERACIÓN DE ERRORES:
   • El sistema ultra-optimizado NO tiene recuperación automática
   • Si se interrumpe: verificar qué se importó y re-ejecutar completo
   • Para importaciones críticas: usar modo --safe

3. VALIDACIÓN:
   • Modo --fast salta validación previa
   • SIEMPRE validar primero con validador_csv.py si datos nuevos
   • Usar --skip-validation solo si CSV ya validado

4. REINDEXACIÓN:
   • Solo una vez al final = más rápido
   • Pero si falla: datos no visibles hasta reindex manual
   • Monitorear logs de reindexación

🎓 MEJORES PRÁCTICAS
═══════════════════════════════════════════════════════════════════════════

1. ANTES DE IMPORTAR:

   □ Backup de Koha: sudo koha-dump koha-cnc

   □ Monitorear recursos (otra terminal): htop
   □ Revisar logs en tiempo real: tail -f logs/*.log
   □ No interrumpir a menos que sea crítico

3. DESPUÉS DE IMPORTAR:
   □ Verificar items en BD
   □ Revisar logs completos
   □ Comprobar OPAC funcional
